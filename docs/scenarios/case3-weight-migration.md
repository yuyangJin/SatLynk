# Case 3: 多模型热切换 — 搬数据 vs 搬权重的相变

## 科学背景

天基智能体星座同时服务多个科学目标：GRB 探测、太阳耀斑分级、引力波对应体搜索。
不同任务需要不同 AI 模型，但单星存储有限（~20 GB 可用于模型缓存），不能缓存所有模型。

太阳活跃期，耀斑频繁触发（一天数十次），但 SolarFlare-CNN 只在 3 颗星上有缓存。
调度器面临"搬数据去远处有模型的星" vs "搬模型到近处的星"的抉择。

**OBS3 相变点**：当重复任务次数超过 `T_migrate / T_remote` 时，提前搬权重是全局最优。

## 参数

| 属性 | 值 |
|------|---|
| 星座 | 3 det + 15 comp, Walker(15/3/1) 550km 53° |
| 模型 | SolarFlare-CNN: 500 MB (INT8), 100M params |
| 模型初始分布 | 仅 comp 节点 3, 7, 11 有缓存 |
| 输入数据 | X 射线通量时间序列 ~500 KB |
| 推理时间 | ~2s on 1 TFLOPS |
| 任务数 | 6 次耀斑，间隔 30s |
| 链路速率 | 50 Mbps (comp↔comp), 2 Mbps (det→comp) |
| 模型迁移时间 | 500 MB / 50 Mbps = 80s |
| 远程传输时间 | 500 KB / 2 Mbps = 2s |

## 验证目标

1. 无权重感知调度：6 个任务排队等 3 颗有模型的星 → 串行瓶颈
2. 有预迁移策略：先花 80s 搬模型到 1-2 颗近星，后续任务并行
3. 量化"搬数据 vs 搬权重"的相变点
