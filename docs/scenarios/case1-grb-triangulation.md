# Case 1: GRB 三角定位 — 多星同时触发的带宽争抢

## 科学背景

伽马射线暴（GRB）的精确天区定位依赖多卫星时间延迟三角测量（TDOA）。
当一次 GRB 被 ≥3 颗探测星同时触发，各星的光变曲线和能谱需要汇聚到
同一颗计算星做联合定位分析。

**为什么要在轨完成**：地面流程（下传→处理→发布 GCN 通告）延迟数十秒到分钟。
在轨完成可将从 GRB 触发到发出定位结果压缩到 <10s，10× 加速后续观测响应。

**文献锚点**：
- 天格 GRID: 10-2000 keV, CsI(Tl) + SiPM, 500-600 km LEO
- 慧眼 HXMT: 每年观测 80-100 个 GRB, 年均数据增量 400-500 MB → 约 5 MB/事件
- GW170817: 引力波 + 短 GRB 联合观测，定位速度决定千新星观测窗口

## 任务流

```
3颗探测星同时触发 GRB
    ↓ (各自产出事件数据包)
[TG-01] ──5MB──→ ┐
[TG-02] ──5MB──→ ├─→ [计算星 X] ──推理 4s──→ 天区概率图 200KB
[TG-03] ──5MB──→ ┘                              ↓
                                          回传给触发星(或地面站)
```

## 观测数据

| 数据产物 | 规格 | 大小 |
|---------|------|------|
| 高时间分辨率光变曲线 | 1ms bin × 60s × 4 能段 = 240,000 点 | ~2 MB |
| 时间分辨能谱 | 256 能道 × 64 时间片 | ~1 MB |
| 辅助数据（时标、温度、背景） | — | ~0.5 MB |
| **单星事件包合计** | — | **~5 MB** |

## AI 模型

| 属性 | 值 |
|------|---|
| 模型 | GRB-Net (Transformer-based 分类+定位联合网络) |
| 参数量 | 500M |
| 权重大小 | 1 GB (INT4 量化) |
| 输入 | 3 星拼接光变曲线 + 能谱 (~15 MB) |
| 推理 FLOPs | ~2×10⁹ |
| 在 1 TFLOPS 芯片上耗时 | ~4 s |
| 输出 | 天区概率图 (HEALPix) + 置信度 + 短暴判断 (~200 KB) |

## 通信参数

| 链路 | 带宽 | 说明 |
|------|------|------|
| 天格星 → 计算星 (det→comp) | 2 Mbps | 天格 6U CubeSat S-band ISL 瓶颈 |
| 计算星 → 计算星 (comp↔comp) | 50 Mbps | 激光通信 |
| 计算星 → 天格星 (comp→det) | 2 Mbps | 同上 |

## 关键冲突

3 颗探测星在 **同一 10 秒窗口** 内发起任务。如果 Nearest-First 把三个都指向
同一颗最近的计算星：
- 带宽被 3 等分: 5 MB / (2 Mbps / 3) = **60 s** 上传
- 加推理 4s + 回传 ≈ **65 s**

如果带宽感知调度器分散到 3 颗不同计算星（各走独立链路）：
- 各自 5 MB / 2 Mbps = **20 s** 上传
- 加推理 4s + 回传 ≈ **25 s**

**Makespan 差距: 2.6×**

## SatLynk 仿真参数

```python
# 星座
detectors = 3   # 535 km SSO, 120° RAAN 间隔
compute = 12    # 550 km, 53° Walker(12/3/1)

# 通信
det_comm_range_km = 3000
det_data_rate_bps = 2e6      # 天格星侧瓶颈
comp_data_rate_bps = 50e6    # 计算星间

# 任务
n_tasks = 3                  # 同时触发
task_arrival_window = 10     # 3 个任务在 10s 内到达
input_size_bytes = 5_000_000 # 5 MB per task
compute_flops = 2e9          # 推理计算量
output_size_bytes = 200_000  # 200 KB 结果
deadline_s = 120             # 2 分钟硬限

# 模型
model_weight_bytes = 1_000_000_000  # 1 GB
```
