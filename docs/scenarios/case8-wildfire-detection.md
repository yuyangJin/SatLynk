# Case 8: 山火检测 — 拍摄-推理-调度耦合管线

## 科学背景

卫星拍摄高分图像后，传统流程下传地面处理（延迟 30min-数小时）。
如果在轨完成火灾检测 CNN 推理，可将发现时间从小时缩短到分钟级。
检测到火灾后，需通过 ISL 通知其他 EO 星优先观测该区域（级联调度）。

2026 WildFIRE-DS 论文 (arXiv:2602.08924) 假设每星自己做推理——
实际上 EO 卫星通常没有强算力（光学载荷占功耗预算），需要 offload。

## 参数

| 属性 | 值 |
|------|---|
| 星座 | 5 EO 卫星 (拍摄+弱算力) + 10 comp, Walker(10/2/1) |
| 单景图像 | ~100 MB (压缩) |
| 火灾检测 CNN | 50M params, 200 MB 权重 |
| 单景推理 | ~3s on 100 TOPS |
| 结果 | 热点坐标+置信度+面积 ~50 KB |
| 后续调度指令 | ~10 KB → 需在 <5min 到达其他 EO 星 |
| 链路 | EO↔comp 10 Mbps, comp↔comp 50 Mbps |

## 任务流（级联）

```
EO-1 拍摄 → offload 给 COMP-3 → 推理 3s → "fire detected!"
    ↓
结果传回 EO-1 + 广播调度指令给 EO-2, EO-3, EO-4
    ↓
EO-2/3/4 调整指向 → 重访该区域 → 贝叶斯融合多次观测
```

## 验证目标

1. "自己算" vs "offload 给算力星" 的端到端延迟
2. 调度指令通过 ISL 传播到 N 颗协同星需要多久（扩散延迟）
3. 能耗预算对一天内"拍摄-推理-确认"循环次数的限制
